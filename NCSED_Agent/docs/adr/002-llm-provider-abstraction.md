# ADR-002. Слой абстракции над провайдером LLM

- **Статус:** принято
- **Дата:** 2026-08-17

## Контекст

Разработка идёт на машине без дискретной GPU (Ryzen 5 5600H, интегрированная
графика) — там локальная модель нежизнеспособна: ~5 ток/сек и до 20 минут
на полный проход по семи шагам.

Запуск и демонстрация — на другом ноутбуке с RTX 4050 (8 GB) через Ollama.

Значит существуют два реальных рантайма, а не один гипотетический. Это
и оправдывает абстракцию: строить её под единственную реализацию было бы
преждевременным обобщением.

## Решение

Пакет `helper_agent/llm/` как единственное место в коде, знающее о провайдере:

- `settings.py` — профиль и параметры из `.env` через `pydantic-settings`;
- `client.py` — фабрика клиента по профилю (`openai` | `ollama`);
- `structured.py` — единая функция получения структурированного ответа;
- `prompts/` — промпты как версионируемые файлы.

Узлы графа вызывают только `structured.py` и о провайдере не знают.

## Где абстракция протекает

Осознанно фиксируем четыре места — от них не спрятаться, их надо обрабатывать
внутри адаптера:

1. **Structured output.** У OpenAI-совместимого API — `response_format`
   с JSON Schema. У Ollama — нативный параметр `format` со схемой, он надёжнее
   их же OpenAI-совместимого пути. Ветвление живёт в `structured.py`.
2. **Tool calling.** Нужен для ReAct-узла поиска. У локальной 8B качество
   вызовов заметно ниже — самое хрупкое место при переезде.
3. **Длина контекста.** Ollama обрезает промпт до `num_ctx` молча, без ошибки.
   Наши few-shot промпты длинные. Значение задаём явно и валидируем на старте.
4. **Детерминизм.** `seed` и `temperature` ведут себя по-разному; полной
   воспроизводимости между профилями не будет.

## Последствия

Переключение профиля — правка `.env`, код не меняется.

Но: **одинаковый код не значит одинаковое поведение.** Промпты, настроенные
на облачной модели, на Qwen3-8B просядут тихо — не сломаются, а станут выдавать
чуть более бедный результат. Поэтому:

- промпты обязаны лежать в файлах и версионироваться;
- eval-харнесс обязан уметь гонять один тест-набор на обоих профилях.

Замеренная разница «облако vs локальная модель» на одинаковых кейсах —
осознанный результат проекта, а не побочный эффект.
